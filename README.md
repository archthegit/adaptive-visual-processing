# adaptive-visual-processing

Standalone research scaffold for query-relevant adaptive visual processing on HD-EPIC VQA.

This repo intentionally implements only the baseline plumbing: HD-EPIC VQA parsing, modular uniform frame sampling, a lazy Qwen2.5-VL wrapper, structured outputs, and placeholders for future query relevance and temporal propagation.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

For the local tests, `numpy`, `pytest`, and a system `ffmpeg`/`ffprobe` are enough. The sampler uses Decord if available, then falls back to `ffmpeg`; Decord is not required for local smoke tests.

Qwen2.5-VL inference dependencies are optional:

```bash
pip install -r requirements-qwen.txt
```

Installing the Qwen dependencies does not download the 7B checkpoint by itself. Checkpoint loading happens only when the baseline is run with `--allow-7b-inference`.

## Expected HD-EPIC Paths

Do not place absolute paths in code. Pass paths at runtime:

```text
annotations/
  vqa-benchmark/
    fine_grained_action_recognition.json
    ...
mp4_dir/
  P01/
    P01-20240202-110250.mp4
  P02/
    ...
```

The MP4 layout follows the official evaluator: `mp4_dir/<participant_id>/<video_id>.mp4`.

## Smoke Test

This writes structured pending records without loading videos or Qwen:

```bash
python3 scripts/run_baseline.py \
  --questions-dir /path/to/vqa-benchmark \
  --limit 5 \
  --dry-run
```

Outputs:


## Frame Count

Local default is intentionally small:

```bash
python3 scripts/run_baseline.py --questions-dir /path/to/vqa-benchmark --dry-run --num-frames 8
```

For the eventual experiment:

```bash
python3 scripts/run_baseline.py \
  --questions-dir /path/to/vqa-benchmark \
  --mp4-dir /path/to/encoded/mp4s \
  --num-frames 128 \
  --allow-7b-inference
```

The script refuses to run 7B inference unless `--allow-7b-inference` is set. The wrapper also refuses if CUDA is unavailable.

## What Is Intentionally Left Open

`src/relevance/base.py` defines:

```python
compute_relevance(question, frames, model_outputs)
```

It does not implement an attention, saliency, patch-selection, or region-selection algorithm. The intended future output shape is already represented by `RelevanceOutput`: frame-level scores, optional spatial maps, selected regions, and metadata.

Optical flow is also not implemented. The `RegionPropagator` protocol and `SpatialRegion` type are placeholders so selected regions can later be propagated between sampled frames without changing dataset or model wrappers.

## Official Behavior Mirrored

The implementation follows the public HD-EPIC repos:

- VQA files are JSON dictionaries keyed by question id.
- Each question has `inputs`, `question`, five `choices`, and `correct_idx`.
- Inputs contain video `id` and either `start_time`/`end_time`, image `time`, or no temporal bounds for full-video questions.
- Answer parsing mirrors the official evaluator by taking the first capital `A`-`Z` and mapping it to a choice index.

Official references inspected:

- https://github.com/hd-epic/hd-epic-vqa-eval
- https://github.com/hd-epic/hd-epic-annotations/tree/main/vqa-benchmark
- https://github.com/QwenLM/Qwen2.5-VL

## Pilot Manifest

Generate the deterministic 50-example pilot subset from official HD-EPIC VQA annotations:

```bash
.venv/bin/python scripts/create_pilot_manifest.py \
  --questions-dir /private/tmp/hd-epic-annotations/vqa-benchmark \
  --pilot-size 50 \
  --seed 20260806 \
  --output-jsonl outputs/pilot_manifest.jsonl \
  --summary-json outputs/pilot_summary.json
```

The pilot prioritizes spatially grounded question families: gaze, fine-grained action, ingredient, object-motion, and 3D perception. It writes a JSONL manifest plus a summary JSON containing full-dataset counts by all 30 question types and broader categories.
