# adaptive-visual-processing

Standalone research scaffold for query-relevant adaptive visual processing on HD-EPIC VQA.

This repo intentionally implements only the baseline plumbing: HD-EPIC VQA parsing, modular uniform frame sampling, a lazy Qwen2.5-VL wrapper, structured outputs, and placeholders for future query relevance and temporal propagation.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

For the local tests, `numpy`, `pytest`, `pillow`, and a system `ffmpeg`/`ffprobe` are enough. The sampler uses Decord if available, then falls back to `ffmpeg`; Decord is not required for local smoke tests.

Qwen2.5-VL inference dependencies are optional:

```bash
pip install -r requirements-qwen.txt
```

Installing the Qwen dependencies does not download the 7B checkpoint by itself. Checkpoint loading happens only when the baseline is run with `--allow-7b-inference`.


The script refuses to run 7B inference unless `--allow-7b-inference` is set. The wrapper also refuses if CUDA is unavailable.

## What Is Intentionally Left Open

`src/relevance/base.py` defines:

```python
compute_relevance(question, frames, model_outputs)
```

It does not implement an attention, saliency, patch-selection, or region-selection algorithm. The intended future output shape is already represented by `RelevanceOutput`: frame-level scores, optional spatial maps, selected regions, and metadata.

Optical flow is also not implemented. The `RegionPropagator` protocol and `SpatialRegion` type are placeholders so selected regions can later be propagated between sampled frames without changing dataset or model wrappers.

## Official Behavior Mirrored

The implementation follows the public HD-EPIC repos:

- VQA files are JSON dictionaries keyed by question id.
- Each question has `inputs`, `question`, five `choices`, and `correct_idx`.
- Inputs contain video `id` and either `start_time`/`end_time`, image `time`, or no temporal bounds for full-video questions.
- Answer parsing mirrors the official evaluator by taking the first capital `A`-`Z` and mapping it to a choice index.

Official references inspected:

- https://github.com/hd-epic/hd-epic-vqa-eval
- https://github.com/hd-epic/hd-epic-annotations/tree/main/vqa-benchmark
- https://github.com/QwenLM/Qwen2.5-VL

## Experiment 1

Experiment 1 is a strictly temporal study. For each single-video HD-EPIC VQA
example, the runner uniformly samples frames, uses Qwen's actual
`video_grid_thw` temporal axis, spatially pools all visual tokens inside each
temporal bin, and tracks how query-conditioned temporal-bin importance changes
across decoder layers. It also records temporal representations from the Qwen
vision patch/merger path when hooks are available, plus adjacent-bin similarity
summaries. Engineering and pilot splits are non-confirmatory; use them only for
debugging and design checks.

Create deterministic temporal splits:

```bash
.venv/bin/python scripts/create_temporal_experiment1_splits.py \
  --questions-dir /path/to/hd-epic-annotations/vqa-benchmark \
  --output-dir outputs/experiment1_temporal_splits \
  --engineering-per-category 2 \
  --pilot-per-category 12 \
  --confirmatory-per-category 60 \
  --max-per-source-video 6 \
  --seed 20260818
```

This writes:

```text
outputs/experiment1_temporal_splits/engineering.jsonl
outputs/experiment1_temporal_splits/pilot.jsonl
outputs/experiment1_temporal_splits/confirmatory.jsonl
outputs/experiment1_temporal_splits/summary.json
```

## Download Manifest Videos

HD-EPIC MP4s are not stored in the annotation repository. To fetch only the videos referenced by a manifest:

```bash
.venv/bin/python scripts/download_manifest_videos.py \
  --manifest outputs/experiment1_temporal_splits/engineering.jsonl \
  --output-dir data/hd_epic_mp4 \
  --dry-run
```

This writes `outputs/manifest_video_download_plan.json` and prints how many unique videos are required. To actually download missing videos:

```bash
.venv/bin/python scripts/download_manifest_videos.py \
  --manifest outputs/experiment1_temporal_splits/engineering.jsonl \
  --output-dir data/hd_epic_mp4 \
  --yes
```

The downloader uses the official Bristol dataset URL pattern:

```text
https://data.bris.ac.uk/datasets/3cqb5b81wk2dc2379fx1mrxh47/Videos/<PID>/<VIDEO_ID>.mp4
```

It skips files already present and stores videos in the layout expected by the runners:

```text
data/hd_epic_mp4/<PID>/<VIDEO_ID>.mp4
```
